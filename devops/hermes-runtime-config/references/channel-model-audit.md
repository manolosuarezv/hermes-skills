# Which model is each channel actually using?

The global config does not answer this. A `/model` switch inside a session is
session-scoped: it changes the running session in place and is NOT written to
`config.yaml`, so a channel can visibly run model B while the global default
still reads model A. Report the evidence line per channel, not the config file.

## Decision order

1. Global default — applies to any session with no override of its own:
```bash
hermes config get model.default
hermes config get model.provider
```
2. Cron jobs carry their own pin; they do NOT follow the global default:
```bash
hermes cron list
python3 -c "import json;d=json.load(open('$HOME/.hermes/cron/jobs.json'));\
[print(j['id'],j['name'],j.get('model'),j.get('provider')) for j in d['jobs']]"
```
3. Per-session state (sqlite) — authoritative for gateway chats:
```bash
cd ~/.hermes
sqlite3 -header -column state.db \
  "SELECT session_key,source,model,datetime(last_activity_at,'unixepoch','localtime') \
   FROM sessions ORDER BY last_activity_at DESC LIMIT 15;"
sqlite3 -header -line state.db "SELECT * FROM gateway_routing;"
sqlite3 -header -line state.db "SELECT * FROM session_model_usage ORDER BY rowid DESC LIMIT 15;"
```
`gateway_routing.model_override` is the persisted per-chat `/model` pin; a row
with no override means that chat simply inherits the global default.
4. Logs — the one line that states what actually ran:
```bash
grep -ah "conversation turn:" ~/.hermes/logs/agent.log | tail -20
grep -ah "Rehydrated persisted /model override" ~/.hermes/logs/gateway.log | tail
grep -ahE "Model switched in-place" ~/.hermes/logs/agent.log | tail
```
5. Fallback chain — what runs when a primary fails:
`hermes fallback list` (or `hermes config get fallback_providers`).

## Reporting rules

- Give a per-channel line: platform, model, provider, and the evidence you read
  it from. Don't summarize the config file as if it were the answer.
- Distinguish "global default" from "switched in place in this session".
- If the user wants a session-only switch to survive new sessions, it must be
  persisted (`hermes config set model.default ...`) — offer that explicitly
  instead of letting them assume it stuck.
- Per-platform pins live under `platforms.<name>.channel_overrides`, keyed by
  `chat_id` / `thread_id` / `parent_id`. A channel with no override inherits
  the global default — easy to misread as "that channel has its own model".
- There is no "mail" channel. AgentMail is an MCP toolset
  (`agentmail: '["hermes-agentmail"]'` in config.yaml), not a platform with a
  model. Mail is generated by whichever session/cron calls the tool; answer by
  naming those sessions'/jobs' models instead.
- Switching model inside a Nous Portal subscription does not lower the monthly
  charge, it only stretches the credits. Say so when a cheaper bill is the
  expected outcome.
